# ТЗ плагина Авито

Общие требования к интерфейсу и синхронизации описаны в [ТЗ MPS](https://github.com/prichinenko/mps/blob/gpt/docs/spec/application.md).

## Подключение

- На уровне сайта хранить Client ID и Client Secret в штатных полях MPS. Секрет не выводить в форме, сообщениях об ошибках и журналах.
- На уровне компании хранить собственный ID аккаунта Авито. Запрашивать доступ через `POST /token` с `grant_type=client_credentials` и проверять владельца через `GET /core/v1/accounts/self`. При несовпадении ID синхронизация должна завершиться до чтения объявлений.
- Использовать реквизиты основного аккаунта. Согласно документации список объявлений под учётной записью сотрудника будет пустым, если объявления принадлежат основному аккаунту.

## Объявления

- Читать `GET /core/v1/items` страницами до 99 записей, запрашивая все пять документированных статусов. Повторная загрузка обновляет строки по паре «компания MPS + ID объявления» и сохраняет существующие связи с Shop-Script.
- Хранить нативный ID объявления отдельно от артикула магазина. Показывать объявления в MPS и без связи с Shop-Script. Переносить название, категорию, статус, ссылку и цену в рублях. Если цена отсутствует в ответе, оставлять её пустой.
- Показывать активные объявления в продаже, завершённые и снятые объявления в архиве, заблокированные и отклонённые в разделе снятых с продажи. Сохранять исходный код статуса.
- Соблюдать документированный лимит списка объявлений в 25 запросов в минуту. Выделять один слот раз в 2,5 секунды на каждый аккаунт в общей очереди установки MPS. При HTTP 429 учитывать `Retry-After`, при его отсутствии ждать 60 секунд. После паузы продолжать с той же страницы.
- Синхронизация читает данные Авито и обновляет каталог MPS. Создание и редактирование товаров Shop-Script в эту операцию не входит.

## Категории

- Показывать категории загруженных объявлений, искать по названию и ID в официальном XML-справочнике Авито. Справочник обновлять раз в сутки. Доступные и связанные категории показывать в штатных вкладках MPS.
- Связь с категорией Shop-Script настраивать в штатном модальном окне.

## Приёмка

- Тестовыми ответами проверить OAuth, несовпадение аккаунта, истечение токена, пагинацию, статусы, цену `null`, устойчивость к сбою и поиск категорий. Проверить общий интервал запросов на одной БД.
- После установки проверить на реальном основном аккаунте количество объявлений, отображение статусов, открытие ссылки и сохранение связи категории.
- Заказы, доставку, сообщения, характеристики, изображения, остатки и запись в Авито специфицировать отдельно по доступным этому аккаунту разделам API.
